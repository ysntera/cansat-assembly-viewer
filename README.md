# CanSat 組立ビューア

ARLISS向けCanSat（2輪ローバー型）の **組み立て手順・部品の役割・機構の動き** を、ブラウザの3Dで学ぶためのページです。

**▶ 公開ページ：https://ysntera.github.io/cansat-assembly-viewer/**（インストール不要。リンクを開くだけで、PC・スマホで見られます）

設計の考え方は、チーム内の資料「CanSat 3D組立・機構ビューア 設計書」（`CanSat/設計・試験/`）にまとめています。

| モード | できること |
|---|---|
| 組み立て | 手順1〜8を1つずつ進める。部品が取り付け方向から飛んできて収まる。手順ごとに説明・写真が出る |
| 部品を見る | 部品をクリック（タップ）すると、名前・役割・材質・個数が出る。分解表示・半透明・この部品だけ表示 |
| ミッション | 収納 → 放出 → 開傘・降下 → 着地 → エンベロープ分離 → スタビライザ展開 → 走行 の7フェーズを再生。走行はボタンで動かせる |

## 1. 開き方

見るだけなら、上の **公開ページ** を開いてください。ここから下は、手元のファイルを直して確かめるときの方法です。

### 1.1 自分のPCで開く

Python が入っていれば、次の2行で開けます（Windows の場合）。

```
cd （index.html があるフォルダ）
py -m http.server 8000
```

1. 1行目で、index.html があるフォルダに移動します。チームの作業フォルダなら `cd CanSat/設計・試験/組立ビューア`、GitHub から取ってきた（clone した）なら `cd cansat-assembly-viewer` です。
2. 2行目を打つと `Serving HTTP on :: port 8000 ...` のような行が出ます。そのままにしておきます。
3. ブラウザ（Chrome・Edge など）で **http://localhost:8000** を開きます。
4. 終わるときは、コマンドを打った画面で `Ctrl + C` を押します。

- Mac・Linux では `py` の代わりに `python3` と打ちます。
- `8000` は「ポート番号」（PCの中の窓口の番号）です。ほかのソフトが使っていてエラーになるときは、`8001` などに変えて、ブラウザでも `http://localhost:8001` を開きます。

### 1.2 index.html をダブルクリックしてはいけない理由

ダブルクリックで開くと、アドレスが `file://...` になります。ブラウザはセキュリティのため、この状態ではページから別のファイル（プログラム・STL・JSON）を読み込めません。部品が表示されず「このままでは表示できません」と出たら、1.1 の方法で開き直してください。

`py -m http.server` は、そのフォルダの中身をブラウザに渡す小さなWebサーバーを、自分のPCの中だけで動かすコマンドです（外の人からは見えません）。

### 1.3 スマホで見る

- 公開ページ（https://ysntera.github.io/cansat-assembly-viewer/ ）を開けば見られます。
- 公開する前に手元の変更を試すときは、PCとスマホを同じWi-Fiにつなぎ、PCで `py -m http.server 8000 --bind 0.0.0.0` を動かして、スマホで `http://（PCのIPアドレス）:8000` を開きます。PCのIPアドレスは、コマンドプロンプトで `ipconfig` と打つと「IPv4 アドレス」に出ます。Windowsのファイアウォールの確認が出たら、「プライベート ネットワーク」だけ許可してください。

### 1.4 操作のしかた

| 操作 | マウス | スマホ・タブレット |
|---|---|---|
| 回す | 左ドラッグ | 1本指でなぞる |
| 拡大・縮小 | ホイール | 2本指で広げる・狭める |
| 平行移動 | 右ドラッグ | 2本指でなぞる |
| 部品の説明（部品を見るモード） | クリック | タップ |
| 手順・フェーズを進める | 「次へ」ボタン、または ← → キー | 「次へ」ボタン |

自分で視点を動かすと、手順を変えても視点はそのままになります。「おすすめの視点に戻す」を押すと、また自動で見やすい向きに移るようになります。

## 2. フォルダの中身

```
組立ビューア/
├── index.html          … ページの枠組み（ボタン・説明欄の置き場所）
├── style.css           … 見た目（色・大きさ・スマホのときの並び方）
├── main.js             … 3D表示と操作の処理（プログラム）
├── data/               … ★内容を直すときは、ここのJSONを直す
│   ├── parts.json      … 部品表（名前・役割・材質・色）
│   ├── placements.json … 各部品の組み上がった位置と向き
│   ├── steps.json      … 組み立て手順
│   └── mission.json    … ミッションの流れ・仮の形の寸法
├── models/             … 部品のSTL（CAD/ からコピーしたもの）
├── photos/             … 組み立て写真（CAD/ からコピーしたもの）
├── media/guide.mp4     … 使い方の動画（README に載せている動画と同じもの）
└── README.md           … この説明
```

**説明文・手順・数値はすべて `data/*.json` にあります。** プログラム（main.js）を触らなくても、JSONを直して保存し、ブラウザを再読み込みすれば画面に反映されます。

## 3. データの直し方

### 3.1 JSONを直すときの注意

JSON（ジェイソン）は、データを書くための決まった書き方です。次の点を間違えると、ページが「書き方（JSONの文法）に誤りがあります」と表示して止まります。

- 文字は必ず `"ダブルクォート"` で囲む（`'シングル'` は使えない）
- 項目と項目の間には `,`（カンマ）を入れる。**最後の項目の後ろには付けない**
- `{ }` と `[ ]` の開き・閉じの数をそろえる
- コメント（`//` など）は書けない

VSCode で開くと、間違いがあるところに赤い波線が出ます。直したら保存して、ブラウザを再読み込み（`F5`）します。画面が変わらないときは `Ctrl + Shift + R`（一時保存を使わずに読み込み直す）を押してください。

座標の向き（CADの座標をそのまま使う。単位は mm）：

| 軸 | 向き |
|---|---|
| x | 車軸の方向（左右） |
| y | 前後。**マイナスが前**（カメラ基板がある側） |
| z | 上下。**プラスが上**。地面は z = −93 |

### 3.2 parts.json（部品表）

部品の種類ごとに1つ書きます（14種類）。

| 項目 | 意味 | 例 |
|---|---|---|
| `id` | 部品の名前（英語）。steps.json などから呼ぶときに使う。**変えると呼び出し側も直す必要がある** | `"layer2"` |
| `file` | `models/` の中のSTLのファイル名。placements.json の `file` と同じにする | `"2nd layer.stl"` |
| `name` | 画面に出す名前 | `"2nd layer（下のトラス板）"` |
| `count` | 機体に使っている個数 | `1` |
| `material` | 材質 | `"ABS（3Dプリント）"` |
| `color` | 画面での色（`#` から始まる6桁の色の番号） | `"#2b3a67"` |
| `role` | 役割の説明文。専門用語には（ ）で短い補足を付ける | |
| `provisional` | （あれば）まだ決まっていない点。一覧に「仮」の札が付き、説明欄にも出る | |
| `split` | （タイヤだけ）1つのSTLの中で色を分ける。`axis` 方向の位置が `below` より小さい部分を `color` で塗る | |

### 3.3 placements.json（部品の位置）

各部品を「部品のSTLの座標」から「組み上がった位置」へ移す回転（`rotation`、3×3）と平行移動（`translation`、mm）です。部品のSTLを全体のSTL（`CAD/CanSat.stl`）に重ね合わせる計算で求めました（設計書5章）。

- 元のデータは `CAD/placements.json` にあります。このフォルダのものはコピーで、`spacer_25mm#2` だけ高さを +1.5mm 直しています（`note` 欄に理由を書いてあります）。
- **CADを更新したら、位置を求め直す必要があります。** 似た形の部品（基板・スペーサー）は別の場所に当てはまりやすいので、求めた位置は必ず画像で確かめてください。
- 手で直すなら `translation` の数字（x, y, z の順、mm）を変えるのが簡単です。

### 3.4 steps.json（組み立て手順）

手順ごとに1つ書きます。並んだ順に表示されます。

| 項目 | 意味 |
|---|---|
| `id` | 手順の番号（画面の表示用。`"2-0"` のような枝番もOK） |
| `title` | 手順の名前 |
| `add` | この手順で付ける部品の `id`（parts.json）のリスト。同じ種類の部品はまとめて付く |
| `direction` | 部品が飛んでくる方向。`[0, 0, 1]` なら上から、`[0, 0, -1]` なら下から、`[0, -1, 0]` なら前から、`[0, 1, 0]` なら後ろから。`"outward_x"` と書くと、左右それぞれの外側から（タイヤなど） |
| `directions` | （あれば）部品ごとに方向を変える。例：`{ "camera": [0, -1, 0] }` |
| `distance` | （あれば）飛んでくる前の距離（mm）。書かなければ 80 |
| `text` | 説明文 |
| `note` | （あれば）補足（青い枠） |
| `fastening` | 固定方法。書かなければ「固定」の行が出ない |
| `tip` | （あれば）豆知識（緑の枠） |
| `provisional` | （あれば）まだ決まっていない点（オレンジの枠） |
| `photos` | `photos/` の中の写真のファイル名のリスト。なければ `[]` |
| `camera` | おすすめの視点。`position` がカメラの位置、`target` が見る点（どちらもCADの座標、mm） |
| `auto_rotate` | （あれば）`true` で、機体を一回りさせる（完成の手順で使用） |

**すべての部品が、どれかの手順の `add` に入っている必要があります。** 入っていない部品があると、読み込み時に画面に知らせが出ます。

写真を足すときは、画像を `photos/` に入れ、`photos` にファイル名を書きます。

### 3.5 mission.json（ミッションの流れ）

**`phases`**（フェーズ。並んだ順に再生）

| 項目 | 意味 |
|---|---|
| `id` / `title` / `text` | 番号・名前・説明文 |
| `action` | 動きの種類。`stowed`（収納）/ `release`（放出）/ `descent`（開傘・降下）/ `landing`（着地）/ `separation`（エンベロープ分離）/ `stabilizer`（スタビライザ展開）/ `drive`（走行）。動きそのものは main.js の `mission_pose` 関数に書いてある |
| `duration_s` | 再生にかける時間（秒） |
| `detail` | （あれば）しくみの説明（青い枠） |
| `provisional` | （あれば）仮の点（オレンジの枠） |
| `camera` | おすすめの視点。`offset` が **機体から見た** カメラの位置、`look` が機体から見た見る点（CADの座標、mm）。カメラは機体について動く |
| `demo` | （走行だけ）最初に見せるお手本の動き。`move` は `forward` / `left` / `right` / `stop`、`seconds` は続ける秒数 |

**`scene`**（高さなど）：`stow_altitude_mm`（キャリアの高さ）、`release_drop_mm`（放出で落ちる量）、`descent_end_altitude_mm`（降下フェーズの終わりの高さ）、`bounce_height_mm`（着地で跳ねる高さ）、`hold_between_phases_s`（自動再生で次のフェーズへ進むまで待つ秒数）。画面で分かりやすくするための値で、実際の高さではありません。

**`shapes`**（CADがない部品の仮の形。設計書12章の「仮」の項目）

| 部品 | 項目 |
|---|---|
| `carrier`（キャリア） | `radius` 半径、`height` 高さ、`color` 色、`opacity` 不透明度（0〜1） |
| `envelope`（エンベロープ） | `radius` 半径、`length` 長さ（車軸方向）、`center` 中心の位置、`open_angle_deg` 開く角度 |
| `parachute`（パラシュート） | `diagonal` 対角の長さ（1400）、`hole_diameter` 中心の穴の直径、`height` 傘の高さ、`knot_height` エンベロープから結び目までの高さ、`rim_above_knot` 結び目から傘のふちまでの高さ |
| `nichrome`（ニクロム線） | `points` 位置（2か所）、`length` 長さ |
| `stabilizer`（スタビライザ） | `width` 幅、`length` 長さ、`anchor` 取り付け位置、`start_angle_deg` 出ていく角度（下向きがマイナス）。曲がり具合は、伸びきったときに先が地面に届くように自動で計算する |

**`drive`**（走行）：`speed_mm_s` 進む速さ、`turn_inner_ratio` 曲がるときの内側のタイヤの速さの割合、`wheel_radius_mm` タイヤの半径、`track_mm` 左右のタイヤの間隔。

## 4. 困ったとき

| 起きたこと | 原因と直し方 |
|---|---|
| 「このままでは表示できません」と出て、部品が出ない | `index.html` をダブルクリックで開いている → 1.1 の方法で開く |
| 「読み込み中…」のまま進まない | 初めて開くときはインターネット接続が必要（6章）。つながっているか確かめる |
| 「models/○○ を読み込めませんでした」「○○ を読み込めませんでした（HTTP 404 …）」 | ファイル名か置き場所が違う。JSONに書いた名前と、フォルダの中のファイル名（大文字・小文字・空白も）が同じか確かめる |
| 「書き方（JSONの文法）に誤りがあります」 | JSONの書き方の誤り（3.1）。メッセージに何行目かが出ていれば、その近くを確かめる |
| 「どの手順にも入っていない部品があります」 | steps.json の `add` にその部品の `id` を足す |
| JSONを直したのに画面が変わらない | `Ctrl + Shift + R` で読み込み直す |
| `py` が見つからないと言われる | Python が入っていない。python.org から入れるか、`python -m http.server 8000` を試す |
| 動きが遅い・カクカクする | 部品の面の数が多い（PCDUだけで約11万面）。ほかのタブを閉じる。古いスマホでは重いことがある |

ブラウザの開発者ツール（`F12` →「Console」）に、もっと詳しいエラーが出ます。

## 6. プログラムについて（main.js を直す人へ）

- 3D表示には **Three.js 0.160.0**（WebGLで3Dを描くライブラリ）を使っています。index.html の `importmap` で、インターネット（jsDelivr）から読み込みます。**初めて開くときはインターネット接続が必要です。** バージョンを変えると動かなくなることがあるので、変えるときは全モードを試してください。
- ビルド（変換）の作業はいりません。main.js を直して保存し、再読み込みすれば反映されます。
- main.js の先頭に、処理の流れと「もの」の親子関係を書いています。モードごとの処理は「組み立てモード」「ミッションモード」「部品を見るモード」の見出しで分けています。
- ブラウザの開発者ツールで `viewer` と打つと、中の状態（部品・手順・カメラなど）を見られます（確認用）。
- 「動きを減らす」設定（OSのアクセシビリティ設定）がオンのときは、アニメーションを短くします。

- `.nojekyll` は、GitHub Pages がファイルを加工せずにそのまま公開するための目印です（消さないでください）。

### 7.1 直した内容を公開ページに反映する

元のファイルは **チームの作業フォルダ**（`CanSat/設計・試験/組立ビューア/`）です。直すのはこちらで、公開用のリポジトリにはコピーして反映します。

1. 作業フォルダで直し、1.1 の方法で動作を確かめる
2. 公開用のリポジトリ（手元では `CanSat/cansat-assembly-viewer/`）を最新にして、ブランチを作る
   ```
   cd CanSat/cansat-assembly-viewer
   git switch main
   git pull
   git switch -c update/内容
   ```
3. 作業フォルダから、公開用のリポジトリへコピーする（PowerShell。`CanSat` フォルダで実行）
   ```
   robocopy "設計・試験\組立ビューア" "cansat-assembly-viewer" /E
   ```
   `/E` は「中のフォルダごとコピー」。ファイルを **消した** ときは、公開用のリポジトリからも手で消す（このコピーでは消えない）
4. `git status` で変わったファイルを確かめ、コミットして push し、プルリクエスト（PR）を作ってマージする
5. マージから1〜2分で公開ページが新しくなる（変わらなければ `Ctrl + Shift + R`）
